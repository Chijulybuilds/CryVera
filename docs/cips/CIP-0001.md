# CIP-0001: Governance and Upgradeability Foundation

Status: Draft

Author: CryVera Protocol Team

Date: 2026-08-03

## Abstract

This CIP proposes introducing a secure governance and upgradeability foundation for CryVera: Safe 2-of-3 multisig for approvals, an OpenZeppelin `TimelockController` enforcing a 72-hour delay, a `ProxyAdmin` owned by the timelock, and `TransparentUpgradeableProxy` instances for selected upgradable contracts.

## Motivation

Enable safe, auditable upgrades while ensuring no single administrator can unilaterally upgrade critical protocol components.

## Proposed Solution

- Deploy a Gnosis Safe multisig (2-of-3) controlled by three owner keys. Safe creates governance proposals and signs transactions to the timelock.
- Deploy OpenZeppelin `TimelockController` with a 72-hour delay. The Safe is a proposer/guardian as appropriate.
- Deploy `ProxyAdmin` and transfer ownership to `TimelockController`.
- Deploy `TransparentUpgradeableProxy` for selected contracts (initially `VeriBridgeVault`, `StrategyManager`, `OracleManager`) and initialize them via `initialize` calls. Ensure implementations call `_disableInitializers()` in constructors.

## Contracts Affected

- `VeriBridgeVault` (upgradeable)
- `StrategyManager` (upgradeable)
- `OracleManager` (upgradeable)
- `RBT` (non-upgradeable)
- `AssetRegistry` (non-upgradeable)

## Deployment Plan

See `script/deploy/governance.s.sol` for a Foundry script that deploys `TimelockController`, `ProxyAdmin`, and demonstrates a proxy deployment pattern.

## Security Considerations

- Storage layout migration must be validated before any upgrade. Use tests to verify state preservation.
- `RBT` remains non-upgradeable to preserve canonical ownership invariants.
